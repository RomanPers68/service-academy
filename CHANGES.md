# Что изменено в этой версии (аудит от 17.08.2026)

Все правки точечные, логика приложения не тронута.

## 1. data/glossary.js
Удалён дубль термина «Стрейнер» (был в двух категориях).
Оставлена версия в «Вино и бар» — рядом с шейкером и барной ложкой.
Чипы терминов в «Сборке» продолжают находить статью.

## 2. App.jsx — гонка загрузки прогресса
Эффект загрузки `progress` из Supabase фильтрует строки по известным
урокам (allValidIds), а СПГ-модули догружаются лениво. При быстром
ответе сервера прогресс роли «Хостес» отфильтровывался как неизвестные
id и перетирал localStorage. Теперь фильтрация ждёт loadSpgModules().

## 3. ui/build.jsx — перезапуск анимаций в «Сборке»
Визуальные носители (Vessel, Station, IcePath и т.д.) объявлены внутри
BuildRunner и рендерились как <Carrier /> — новый тип компонента на
каждый рендер, React пересоздавал их DOM целиком: анимация заливки,
льда и пузырьков перезапускалась даже при открытии чипа глоссария.
Теперь носители вызываются функциями ({Carrier()}), DOM сохраняется,
«fresh»-анимации играют только при реальном появлении нового слоя.
Плюс убран задублированный ключ color в StepList.

## Рекомендации без правок (на твоё решение)
- css.js: добавить `.sa-aiinput-light::placeholder` (стиль есть только
  для тёмной темы; в светлой плейсхолдер — браузерный серый).
- /api/assistant: нет rate-limit и проверки сессии — эндпоинт открыт,
  любой может расходовать токены. Стоит проверять sa_session_token.
- У 25 из 68 шагов «Сборки» термин без статьи в глоссарии (чип плоский):
  деэскалация, инвентаризация, тайминг, гигиена, допродажа и др.

# Дополнение 47 — очистка графика: безопасная и адресная
Два вопроса владельца, оба закрыты:
1) «Нечаянно очистил — спасёт „Отменить"?» Раньше — только отчасти:
   очистка МГНОВЕННО сохраняла пустоту на сервер, и «Отменить» помогал,
   лишь пока человек не ушёл с экрана. Теперь очистка — локальный
   черновик: сервер не трогается до осознанного «Сохранить». Случайная
   очистка безобидна всегда: «↩ Отменить» вернёт, а закрытие приложения
   просто оставит сервер прежним. Панель прямо предупреждает об этом.
2) «Можно стереть смены выборочно?» Теперь да: кнопка «Очистить месяц»
   открывает панель с тремя областями — весь месяц, одна должность
   (чипы по позициям, где есть люди) или один сотрудник (выпадающий
   список). Стираются и смены, и закрепления выбранной области; всё
   через снапшот отмены и черновик.

# Дополнение 66 — «три полоски»: первопричина найдена и убита
Развязка детектива трёх ходов. Метка «ГРАФИК · V64» подтвердила: код

оставались только рамки («полоски»). Это объясняет весь парадокс:
старые «простыни» (div без overflow) не сжимались и были видны;

флекс-дети) — потому работали; а те же Sec-и на странице графика —
прямые дети флекса — исчезали и внизу (Доп. 63), и вверху (Доп. 65).
Фикс — одна строка: flexShrink:0 в контейнере Sec. Метка версии в

# Дополнение 75 — удаление: умное сопоставление профиля со списком доступа
Прод-репорт: «в базе есть, а пишет, что нет». Причина: карточки живут
по ПРОФИЛЯМ (как человек записал себя при входе), а удаление ищет в
СПИСКЕ ДОСТУПА (как записал руководитель в «Команде») — «Заяц

похожих → честный отказ со списком кандидатов и советом удалить
точечно через «Команду»; ноль → сообщение с числом проверенных.

порядок/регистр/ё-е/частичное имя — совпадают, чужие и пустые — нет.
