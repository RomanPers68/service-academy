# Подключение AI-ассистента «Наставник» (бесплатно)

Ассистент работает через Supabase Edge Function `ai-chat` — она хранит ключ
ИИ-провайдера на сервере и отвечает только сотрудникам с валидным кодом
(проверка через твою же функцию `whoami`). Провайдер — OpenRouter: один ключ,
десятки моделей, есть бесплатные. Настройка ~7 минут, по шагам:

## Шаг 1. Ключ OpenRouter (2 мин)
1. Зарегистрируйся на https://openrouter.ai (можно через Google/GitHub).
2. Меню → **Keys** → **Create Key** → назови «Service Academy» → скопируй ключ
   (начинается с `sk-or-…`). Больше он не покажется — сохрани.
3. Платить не нужно: используем модель с пометкой `:free`.

## Шаг 2. Развернуть функцию (3 мин)
1. Supabase → твой проект → в левом меню **Edge Functions**.
2. **Deploy a new function** → способ **Via Editor** (прямо в браузере).
3. Имя функции: `ai-chat` (ровно так).
4. Сотри заготовку и вставь целиком содержимое файла
   `supabase/functions/ai-chat/index.ts` из проекта.
5. **Deploy**.

## Шаг 3. Секреты (2 мин)
1. Edge Functions → **Secrets** (или Settings → Edge Functions → Secrets).
2. Добавь секрет: имя `OPENROUTER_API_KEY`, значение — ключ из шага 1.
3. (Необязательно) секрет `OPENROUTER_MODEL`, если хочешь другую модель.
   По умолчанию: `deepseek/deepseek-chat-v3-0324:free` — хороший русский,
   бесплатно. Альтернативы смотри на openrouter.ai/models (фильтр Free).

## Шаг 4. Проверка
Открой приложение → на главной жетон **«Ассистент»** → задай вопрос
(например, «Гость недоволен блюдом — что говорить?»). Ответ должен прийти
за 2–8 секунд.

## Если что-то не так
- **«Ассистент ещё не подключён»** — функция не задеплоена или нет секрета
  `OPENROUTER_API_KEY` (проверь имя — ровно так, без пробелов).
- **«Бесплатный лимит исчерпан»** — у free-моделей дневная квота
  (~50 запросов/день без пополнения; положи $10 на счёт OpenRouter — лимит
  free-моделей вырастет до 1000/день, деньги не списываются).
- **Долго думает / ошибка провайдера** — free-модели иногда перегружены:
  подожди минуту или смени модель через секрет `OPENROUTER_MODEL`.
- Логи функции: Edge Functions → ai-chat → **Logs** — там видно каждую ошибку.

## Когда пойдёте в прод
Смени секрет `OPENROUTER_MODEL` на платную модель и пополни баланс OpenRouter. С v67 рекомендуемая —
`anthropic/claude-haiku-5.5` (см. раздел «Переход на Claude Haiku 5.5» ниже: сначала обнови функции,
потом меняй секрет). Секрет общий: им пользуются Наставник, «Живой гость» и AI HR.

## Переход на Claude Haiku 5.5 (v67)

Haiku 5.5 (вышла 7 октября 2026) по данным Anthropic умнее Haiku 4.5 и примерно в 8 раз дешевле на наших
запросах: $0,10 за миллион токенов запроса и $0,50 за миллион токенов ответа (при запросе до 100 тысяч токенов;
у нас все короче). Но устроена иначе, поэтому **сначала код, потом секрет**:
- не принимает `temperature` (Haiku 5.5 отвечает ошибкой на любое значение, кроме 1);
- сама размышляет перед ответом, и размышления тратят тот же лимит длины ответа;
- её токенизатор считает тот же текст примерно на 30% длиннее.

Функции v67 это учитывают: `temperature` для новых моделей Claude не шлют, лимиты подняты. Размышления —
по задачам: в живом разговоре (реплики «Живого гостя», вопросы интервьюера, Наставник голосом) выключены — там
важна скорость; оценка собеседования — с размышлениями среднего уровня; разбор «Живого гостя» и Наставник
текстом — лёгкого (на простой вопрос модель не думает). С Haiku 4.5 и бесплатными моделями всё как раньше.

Порядок:
1. Edge Functions → `ai-chat` → **Code** → вставь целиком новый `supabase/functions/ai-chat/index.ts` → **Deploy**.
2. Edge Functions → `ai-hr` → **Code** → вставь целиком новый `supabase/functions/ai-hr/index.ts` → **Deploy**.
   С этим кодом всё работает и на прежней модели — можно не спешить с шагом 3.
3. Edge Functions → **Secrets**: `OPENROUTER_MODEL` = `anthropic/claude-haiku-5.5`;
   `OPENROUTER_FALLBACK_MODEL` = `anthropic/claude-haiku-4.5` — запасная для AI HR, если основная не ответит.
4. Проверка: задай Наставнику вопрос текстом и голосом, сыграй минуту с «Живым гостем».
   Не отвечает — верни в `OPENROUTER_MODEL` прежнее значение и пришли разработчику строку из
   Edge Functions → ai-chat → **Logs**.
5. «Собеседование» → строка «AI HR» → «Запустить проверку». Итог прошлой проверки (на Haiku 4.5) после первого
   же интервью на новой модели перестанет засчитываться — приложение напишет «проверить на новой модели».

## Кэш подсказки Наставника (v67)

Наставник при каждом вопросе отправляет модели около 60 тысяч знаков: правила, этапы визита, карту приложения
и программу уроков. Теперь эта постоянная часть одна на всех сотрудников и идёт первой с пометкой кэша
(Anthropic через OpenRouter): модель читает её из кэша за 10% цены, а кто спрашивает, его позиция и регламенты
ресторана идут после неё. Первый вопрос после часа тишины записывает кэш (запись на час — 2× цены), каждое
следующее чтение продлевает час. Уточняющий вопрос в течение 5 минут читает из кэша и весь разговор.
В приложении ничего не меняется; ответ начинается быстрее, потому что длинную подсказку модель не перечитывает
заново. Где видно: OpenRouter → **Activity** → запрос → строка о кэше (скидка на прочитанное); в
Edge Functions → ai-chat → **Logs** — строка `ai-chat usage … "cached": …` (сколько токенов прочитано из кэша).

# AI HR: функция `ai-hr` (интервьюер собеседований)

Вторая Edge Function — ИИ-интервьюер для «Собеседования кандидата».
Разворачивается так же, как ai-chat, за 3 минуты:

1. Supabase → **Edge Functions** → **Deploy a new function** → **Via Editor**.
2. Имя: ровно `ai-hr`.
3. Вставь целиком содержимое `supabase/functions/ai-hr/index.ts` → **Deploy**.
4. Секреты добавлять НЕ нужно: `OPENROUTER_API_KEY` общий для всего проекта
   и уже задан при настройке ai-chat.

Проверка: Команда → Собеседование кандидата → заполни имя и опыт →
на экране «Передайте телефон кандидату» появится кнопка
**«🤖 AI-интервью · бета»** — ИИ поздоровается и задаст первый вопрос.
После 4+ ответов появится «Завершить интервью → оценка»: результат
запишется в ту же историю собеседований, с вердиктом ИИ и оценками
по компетенциям (и уйдёт в облако, как обычные).

Важно: ИИ может ошибаться — финальное решение о найме всегда за менеджером
(эта приписка есть и на экране интервью).

## AI HR v2 (v66): интервью по плану, отчёт с доказательствами, снятие «беты»

Что поменялось в функции `ai-hr` (Дополнение 379):
- **План интервью ведёт сервер**: пять тем должности по порядку, по каждой — вопрос из банка и не больше
  одного уточнения, после последней темы интервьюер прощается. В приложении — «Тема 2 из 5» и полоски.
- **Оценка с доказательствами**: по каждой теме — балл, «почему» и цитата кандидата; 2 прогона оценки
  (третий — если разошлись), середина; категория — по правилу из баллов и красных флагов; «ИИ не уверен»;
  что спросить на живой встрече. Учитывается заявленный опыт (новичка не штрафуем за термины, от 3+ ждём
  конкретики) и то, что ответы могли быть надиктованы голосом.
- **Модель**: `OPENROUTER_MODEL` (два захода), потом — необязательный секрет **`OPENROUTER_FALLBACK_MODEL`**
  (запасная модель, если основная не ответила). В отчёте видно, какая модель оценивала.

Как обновить:
1. Supabase → **Edge Functions** → `ai-hr` → **Code** → вставь целиком новый
   `supabase/functions/ai-hr/index.ts` → **Deploy**. Старое приложение с новой функцией работает как раньше.
2. SQL Editor → запусти **`supabase/supabase-stage28-ai-hr.sql`** целиком: «Ваше решение» по кандидату
   (Берём / Подумаю / Не берём) и общий для руководителей итог «Проверки AI HR». Заодно история собеседований
   теперь видна только руководителям своего ресторана.
3. (Необязательно) Edge Functions → **Secrets** → `OPENROUTER_FALLBACK_MODEL` — например, другая модель
   на случай, если основная недоступна.

Когда снимается «бета» — сама, при двух условиях:
1. **Эталонная проверка**: Собеседование → строка «AI HR · бета» → «Запустить проверку». 22 собеседования
   с заранее известным итогом (сильные и слабые, голосом с ошибками, грубость, обман, попытка повлиять на
   оценку) идут через ту же оценку; нужно совпадение 90%+ и ни одного пропущенного красного флага.
   Займёт 3–5 минут, это около 50 обращений к модели. Сменили модель — запустите проверку ещё раз.
2. **Ваши решения**: в отчёте AI-интервью отмечайте «Берём» или «Не берём»; на последних 20 собеседованиях
   с решением ИИ должен совпасть с вами в 80%+.

## Обновить ассистента (когда меняется приложение или уроки)

Ассистент знает приложение и программу из подсказки внутри функции `ai-chat`.
Когда появились новые разделы или уроки:

1. Карта уроков собирается скриптом из данных программы:
   `node tools/claude/gen-lesson-map.mjs` (из корня проекта) — он перепишет карту
   в `supabase/functions/ai-chat/index.ts` между метками `<LESSON_MAP:BEGIN/END>`.
   Руками карту не править.
2. Карта приложения, правила и кнопки-переходы — там же, в тексте подсказки
   (разделы «КАРТА ПРИЛОЖЕНИЯ», «КАК ЭТО РАБОТАЕТ», «СЕКРЕТЫ», «КНОПКИ-ПЕРЕХОДЫ»).
   Новая кнопка должна быть и в подсказке, и в приложении: подпись — `NAV_LABELS`
   в `ui/assistant.jsx`, экран — карта `GO` в `App.jsx`.
3. Supabase → **Edge Functions** → `ai-chat` → вкладка **Code** → выделить всё →
   вставить новое содержимое `supabase/functions/ai-chat/index.ts` → **Deploy**.

## Ассистент редактора контента (/api/lesson-assist)

Кнопки «Урок из текста», «Улучшить текст», «Придумать вопросы» в редакторе контента
работают через серверную функцию Vercel `api/lesson-assist.js`. Она берёт тот же ключ
`OPENROUTER_API_KEY`, что импорт меню: если импорт меню работает — настраивать ничего
не нужно, функция появится сама после заливки архива на Vercel.

- Модель по умолчанию — `google/gemini-2.5-flash` (дешёвая, пишет по-русски, читает PDF),
  запасная — `anthropic/claude-sonnet-4.6`. Сменить — переменная `OPENROUTER_LESSON_MODEL`.
- Только для руководителей (как сам редактор), не больше 40 обращений в час на человека.
- Всё приходит черновиком: сохраняет урок только человек.
