# Supabase — что и в каком порядке применять

Файлы запускаются в SQL Editor **по порядку сверху вниз**. Каждый можно
запускать повторно: они написаны так, чтобы не ломаться на уже созданном
(`create ... if not exists`, `create or replace`). Внизу каждого файла есть
проверка — сколько таблиц и функций получилось.

**После этапа 21 файлы 20–20e заново не запускай.** Они вернули бы старые версии
сброса прогресса, разблокировки тестов и «Моего прогресса» — без проверки ресторана.
А 20б и 20г ещё и стёрли бы прогресс сотрудника из своей ручной чистки. Эти два файла
теперь сами останавливаются, если этап 21 уже есть.

### Этап 21 — порядок выкатки

1. Выполнить `supabase-stage21-private-data.sql` — старое приложение продолжает работать.
2. Выложить новую версию приложения. Она читает рейтинг, прогресс и карточки
   сотрудников через функции этапа 21, а если их на сервере нет — по-старому.
3. Через день-два — `supabase-stage21b-close-tables.sql`. В конце он печатает
   «прямой доступ anon к таблицам: 0» и список функций, доступных без токена
   (ожидаем только `menu_get`, `redeem_code`, `sa_rank`).
4. Если после шага 3 что-то перестало показываться — `supabase-stage21b-rollback.sql`.

### Этапы 22 и 22б (v28)

1. `supabase-stage22-hall-confirm.sql` — можно сразу (после этапа 21). Без него
   кнопка «Отправить старшему» честно говорит, что сервер не обновлён, PIN работает.
2. `supabase-stage22b-telegram-reminders.sql` — по желанию. Перед запуском: включить
   pg_net и pg_cron (Database → Extensions), положить токен бота в Vault
   (`select vault.create_secret('ТОКЕН', 'sa_tg_bot_token');`) и адрес приложения в
   `sa_settings` (`app_url`). Файл в конце печатает, всё ли на месте. Проверка без
   отправки: `select sa_warmup_preview();`. Часовой пояс по умолчанию — Камчатка.

### Этап 23 (v29)

`supabase-stage23-reports.sql` — можно сразу (после этапа 21), ничего не ломает.
В конце печатает «отчёты: 6 функций из 6, таблиц 2 из 2». Права: сотрудник видит
только себя; менеджер — свой ресторан (без старших); старший — всех ниже себя во
всех ресторанах; владелец — всех. Без этапа экран отчётов честно пишет, что нужно
его применить, а телефон молча не шлёт копию — приложение работает как раньше.
Скачивание в Telegram идёт через `/api/report` (Vercel) — переменные те же, что
у `/api/backup`.

## Важно для новых этапов: whoami только через whoami_txt

На этой базе `whoami` принимает токен не текстом (например, uuid). Внутри SQL прямой
вызов `whoami(p_token)` с текстовым токеном падает: «function whoami(text) does not
exist» — так было с этапами 4–10 (починил 11c) и снова с 15–16. Новые функции зовут
`whoami_txt(p_token)` — переходник из этапа 11c; этапы 4–10 и 15–17 сами создают его, если
его нет (старые этапы переведены на него в правке 151). И в конце каждого этапа — `notify pgrst, 'reload schema';`, иначе приложение
может не увидеть новые функции (см. этап 9).
