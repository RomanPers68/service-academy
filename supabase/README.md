# Supabase — что и в каком порядке применять

Файлы запускаются в SQL Editor **по порядку сверху вниз**. Каждый можно
запускать повторно: они написаны так, чтобы не ломаться на уже созданном
(`create ... if not exists`, `create or replace`). Внизу каждого файла есть
проверка — сколько таблиц и функций получилось.

**После этапа 21 файлы 20–20e заново не запускай.** Они вернули бы старые версии
сброса прогресса, разблокировки тестов и «Моего прогресса» — без проверки ресторана.
А 20б и 20г ещё и стёрли бы прогресс сотрудника из своей ручной чистки. Эти два файла
теперь сами останавливаются, если этап 21 уже есть.

### Этап 21 — порядок выкатки

1. Выполнить `supabase-stage21-private-data.sql` — старое приложение продолжает работать.
2. Выложить новую версию приложения. Она читает рейтинг, прогресс и карточки
   сотрудников через функции этапа 21, а если их на сервере нет — по-старому.
3. Через день-два — `supabase-stage21b-close-tables.sql`. В конце он печатает
   «прямой доступ anon к таблицам: 0» и список функций, доступных без токена
   (ожидаем только `menu_get`, `redeem_code`, `sa_rank`).
4. Если после шага 3 что-то перестало показываться — `supabase-stage21b-rollback.sql`.

### Этапы 22 и 22б (v28)

1. `supabase-stage22-hall-confirm.sql` — можно сразу (после этапа 21). Без него
   кнопка «Отправить старшему» честно говорит, что сервер не обновлён, PIN работает.
2. `supabase-stage22b-telegram-reminders.sql` — по желанию. Перед запуском: включить
   pg_net и pg_cron (Database → Extensions), положить токен бота в Vault
   (`select vault.create_secret('ТОКЕН', 'sa_tg_bot_token');`) и адрес приложения в
   `sa_settings` (`app_url`). Файл в конце печатает, всё ли на месте. Проверка без
   отправки: `select sa_warmup_preview();`. Часовой пояс по умолчанию — Камчатка.

### Этап 23 (v29)

`supabase-stage23-reports.sql` — можно сразу (после этапа 21), ничего не ломает.
В конце печатает «отчёты: 6 функций из 6, таблиц 2 из 2». Права: сотрудник видит
только себя; менеджер — свой ресторан (без старших); старший — всех ниже себя во
всех ресторанах; владелец — всех. Без этапа экран отчётов честно пишет, что нужно
его применить, а телефон молча не шлёт копию — приложение работает как раньше.
Скачивание в Telegram идёт через `/api/report` (Vercel) — переменные те же, что
у `/api/backup`.

### Этап 24 (v30)

`supabase-stage24-together.sql` — после этапа 23, ничего не ломает. В конце печатает
«вместе: 7 функций из 7, таблица пар: есть». Данные — та же копия с телефонов (этап
23), поэтому квест и лига обновляются в течение пары минут после занятия. Часовой пояс —
как у напоминаний: свой у заведения (`sa_settings`, ключ `tz:<заведение>`), иначе общий
(`tz`), иначе Камчатка; ошибка в названии пояса ничего не ломает. Копии с телефона сервер
не верит на слово: числа — от 0 до 1000, очки и дни считаются только за настоящие даты
календаря, не больше 200 очков в день. Выходной по графику (этап 9) свечу на двоих не гасит; пару, где кого-то уже нет
в команде, сервер гасит сам. Без этапа приложение работает: личные задания квеста и свои
очки лиги считаются на телефоне, свеча на двоих просит обновить сервер.

«Живой гость» — режим той же функции `ai-chat` (новая версия папки
`functions/ai-chat`): `supabase functions deploy ai-chat`. Отдельный лимит — 40 запросов в
день на сотрудника. Характеры гостей хранятся в самой функции (телефон присылает только
номер персонажа). Без ИИ гость идёт по сценарию.

### Этап 26 (v40)

`supabase-stage26-mastery.sql` — после этапа 25, ничего не удаляет; можно запускать повторно.
В конце печатает «путь мастера: функции 3 из 3, таблица мастеров: есть, вид «master»: есть · «Шаг дня»
в напоминании: есть · Telegram: есть».
Что даёт: список мастеров своего заведения (знак ✦ у имени в рейтинге и лиге, баннер в «Команде»),
сообщение коллегам «… стал(а) мастером роли «…» ✦» (каждому — не больше одного такого в день, выключается
в «Что ещё присылать» → «Мастера заведения»), приз для мастеров (до 200 знаков, назначает руководитель
на экране «Путь мастера»), строка «Шаг дня: …» в напоминании за час до смены.
Значки и шаг дня считаются в телефоне — без этапа 26 они работают, нет только мастеров заведения,
приза и сообщений.

Важно: этапы 22б и 25 пересоздают напоминание и настройки сообщений по-своему. Если запускаешь один
из них заново после этапа 26 (или включаешь 22б впервые) — запусти потом и этап 26 ещё раз.

### Этап 25 (v31)

`supabase-stage25-live.sql` — после этапа 24, ничего не ломает; можно запускать повторно.
В конце печатает «живая академия: 13 функций из 13, таблиц 7 из 7 · Telegram: … · pg_cron: …».
Что даёт: квест, свеча на двоих и место в лиге приходят одним запросом (`day_brief`); занятие
отмечается на сервере сразу (`sa_day_push` — только сегодняшний день ±1, числа от 0 до 1000,
берётся большее из пришедшего и сохранённого); «Спасибо команде» и «Позвать на разминку» в
квесте (звать может старший, раз в день); «Подтолкнуть» в свече на двоих (раз в день); история
лиги и кубка (прошлая неделя записывается сама, когда во всех часовых поясах сети уже понедельник
после 06:00; пропущенные недели — до четырёх — добираются);
рекорды раунда мастера; свои гости заведения для «Живого гостя» (пишет руководитель, до 30).

Сообщения бота по расписанию — если есть этап 22б (бот и Vault) и включён pg_cron: файл сам
ставит задачу `sa-nudges` (каждые 10 минут; что уйдёт сейчас — `select sa_nudges_preview();`).
Вечером 18–21 — «напарник уже занимался, твоя очередь»; понедельник 10–21 — итоги лиги; четверг
12–20 — выдыхающиеся темы (от трёх); 1-е число 12–20 — итоги месяца. Каждый вид — не чаще раза
в день, только тем, у кого включены напоминания; каждый выключается в приложении («Напоминания
в Telegram» → «Что ещё присылать»). Без pg_cron всё остальное работает.

Корзина `radio-voice` (публичная, только mp3 до 2 МБ, без списка файлов) и счётчик `sa_tts_usage` —
для «живых голосов» радио. Нужны, только если развёрнута функция `radio-tts`.

После этапа — заново развернуть `ai-chat` (свои гости заведения, ответы гостя потоком, ключи
`sb_secret_…`): `supabase functions deploy ai-chat`. По желанию — `radio-tts` (см. ниже).

Этап 22б (обновлённый файл): финальная проверка больше не падает, если pg_cron не включён, —
можно запускать повторно.

`supabase-stage11-rollback.sql` — откат одиннадцатого шага, если после
закрытия доступа что-то перестало работать. В обычной жизни не нужен.

## Функции (папка `functions/`)

Разворачиваются отдельно, командой `supabase functions deploy <имя>`:

| Функция | Зачем |
|---|---|
| `ai-chat` | Наставник: ответы по урокам, меню и бару |
| `ai-hr` | Собеседование кандидата |
| `photo-upload` | Фото блюд: приём, сжатие, ссылка |
| `stt` | Распознавание речи для голосового ввода |
| `daily-reminder` | Утреннее напоминание в Telegram |
| `shift-reminder` | Напоминание о смене |
| `radio-tts` | «Живые голоса» радио (v31, по желанию): секрет `OPENAI_API_KEY` (модель — `OPENAI_TTS_MODEL`, по умолчанию `gpt-4o-mini-tts`; голоса — `RADIO_TTS_VOICES`, например `host:nova,guest:onyx,staff:coral`). Каждая фраза озвучивается один раз и лежит в корзине `radio-voice` (этап 25). Лимит — 400 новых фраз и 40 000 знаков в день на сотрудника (счёт на сервере, этап 25: `sa_tts_take`); без этапа 25 живых голосов нет. Без ключа приложение читает голосом телефона |

Ключи к ним живут в переменных окружения проекта Supabase, в репозитории их нет.

## Важно для новых этапов: whoami только через whoami_txt

На этой базе `whoami` принимает токен не текстом (например, uuid). Внутри SQL прямой
вызов `whoami(p_token)` с текстовым токеном падает: «function whoami(text) does not
exist» — так было с этапами 4–10 (починил 11c) и снова с 15–16. Новые функции зовут
`whoami_txt(p_token)` — переходник из этапа 11c; этапы 4–10 и 15–17 сами создают его, если
его нет (старые этапы переведены на него в правке 151). И в конце каждого этапа — `notify pgrst, 'reload schema';`, иначе приложение
может не увидеть новые функции (см. этап 9).
