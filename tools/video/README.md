# tools/video — титры для видео-знакомств

Не часть приложения: Vite сюда не заглядывает. Здесь то, чем сделаны ролики в `public/video` (v174, Доп. 499),
чтобы новый ролик или новую версию старого собрать так же.

| Файл | Что внутри |
|---|---|
| `scripts.md` | Тексты сценариев для HeyGen (паузы `<break>`, без тире, числа словами) и образ аватара для каждой роли |
| `chunks/<роль>_chunks.txt` | Те же тексты по плашкам: одна строка — одна плашка, `!` в начале — главная мысль на золотой плашке |
| `fa.py` | Привязка слов к звуку: модель голоса учится на самих роликах, слово — с точностью до сотых секунды |
| `make_captions.py` | Титры в формате ASS: тёмно-синяя плашка с золотой кромкой, Inter ExtraBold, слово подсвечено золотом |
| `cues.py` | v175: начала предложений из того же времени слов — по ним плеер перематывает «назад / вперёд на фразу» |
| `compare.py` | v176: звук нового ролика против старого — что поменялось после пересъёмки и где время слов можно взять прежнее |

Нужны Python 3 с numpy, scipy и Pillow, ffmpeg с libass и шрифт Inter (`/usr/share/fonts/opentype/inter`).

## Как собрать

```bash
# 1. звук из ролика HeyGen (без титров)
ffmpeg -i spg.mp4 -vn -ac 1 -ar 16000 spg.wav

# 2. время каждого слова; лучше все роли сразу: голос один, модель учится на всех роликах
python3 fa.py out spg:chunks/spg_chunks.txt:spg.wav bar:chunks/bar_chunks.txt:bar.wav   # → out/spg_fa.json, out/bar_fa.json

# 3. титры
python3 make_captions.py chunks/spg_chunks.txt --times out/spg_fa.json -o spg.ass

# 4. титры в кадр и сжатие для приложения (720×1280). v178 (Доп. 503): легче для слабой связи — не больше 550 кбит/с
#    на картинку (среднее — 0,4–0,55), ключевой кадр каждые 4 с (перемотка и продолжение после паузы быстрее), звук моно
#    64 кбит/с: 2,7–3,9 МБ на ролик. До v178 было -preset veryfast -crf 26, -b:a 96k: 3–6,2 МБ и до 1 Мбит/с
ffmpeg -i spg.mp4 -vf "ass=spg.ass:fontsdir=/usr/share/fonts/opentype/inter" -c:v libx264 -preset slow -crf 30 \
  -maxrate 550k -bufsize 1100k -g 100 -keyint_min 25 -pix_fmt yuv420p -profile:v high \
  -c:a aac -b:a 64k -ac 1 -movflags +faststart ../../public/video/intro-spg.mp4
# заменили ролик — в data/intro-videos.js новый rev (первые 8 знаков sha256sum файла): иначе телефоны, взявшие ролик
# заранее, играли бы прежний (lib/intro-warm.js)

# 5. обложка — кадр с улыбкой на «Привет!» (около 1,3 с)
ffmpeg -ss 1.3 -i spg.mp4 -frames:v 1 -q:v 4 ../../public/video/intro-spg.jpg
```

Потом — в `data/intro-videos.js` (v175, Доп. 500):

- `dur` — длительность в секундах;
- `cues` — начала предложений: `python3 cues.py out/spg_fa.json` (начало первого слова и каждого слова после точки,
  «!», «?» или многоточия);
- `face` — где на обложке лицо, доли высоты кадра `intro-<роль>.jpg`: макушка, глаза, подбородок (на глаз, по сетке
  через 2 %). По ним обложка в уроке и в разделе ставит кадр так, чтобы лицо было видно (`lib/intro-video.js`).

## На что смотреть

- Слова в `chunks/` должны совпадать со сценарием буква в букву: `fa.py` выравнивает именно их. Знаки препинания
  важны: после точки или запятой пауза ожидаема, внутри фразы — редкость.
- Плашка — не больше двух строк. Длинную главную мысль делим на две плашки (так в «Баре»: «порядок на станции» /
  «даёт скорость без спешки»).
- Проверка тайминга: в выводе `fa.py` паузы больше 0,2 с почти все стоят после знаков препинания. Если пауза
  оказалась внутри фразы, стоит открыть спектрограмму этого места.
- `make_captions.py --audio` без `fa.py` делит время участка речи между словами по длине — ошибка до 0,3 с, только
  для черновика.

## Ролик пересняли (v176, Доп. 501)

Так было 18.11: все шесть роликов пересняты, текст прежний, кроме реплики сервис-менеджера. Порядок:

1. Звук нового ролика (шаг 1 выше) и сравнение со старым: `python3 compare.py old.wav new.wav out/<роль>_fa.json`.
   Тогда до последней фразы сдвиг был 0,00–0,01 с, отличался только конец: пауза перед «Начнём!» длиннее на 0,3–0,4 с,
   после него — около 0,7 с тишины; у сервис-менеджера — весь последний абзац (его синтез сделан заново).
2. Привязка `fa.py` по всем новым роликам сразу (шаг 2 выше), потом время слов: где звук совпал — из старой привязки
   (она проверена по спектрограмме), с изменённого места — из новой. Так короткое «Мы» в «Баре» не уехало в паузу:
   новая модель снова ставила его на 0,6 с раньше.
3. Титры, сжатие и обложка — шаги 3–5; обложку — на улыбке и без руки в кадре (в новом «Ядре» на 1,3 с машет рукой).
4. В `data/intro-videos.js` — новая `dur` и `cues`; `face` проверить по сетке на новой обложке.

Какая реплика звучит, если текста под рукой нет: модель звуков из `fa.py`, обученная на остальных роликах, оценивает
звук при разных вариантах фразы — у верного варианта вероятность заметно выше. Так 18.11 нашлось «а всё работает как
часы»; «а ничего не работает как часы» и прежнее «а ничего не рассыпалось» шли далеко позади.

## Новый ролик с тем же текстом (v194, Доп. 519)

25.11 владелец прислал новый ролик сервис-менеджера: тот же аватар и фон, текст тот же, но синтез новый и темп
быстрее (52 с вместо 55). `compare.py` показал ровно растущий сдвиг до −2,9 с к концу и ни одного участка с другим
текстом. Поэтому старое время слов не годится нигде: `fa.py` по новому звуку целиком (вместе с остальными пятью
ролями, шаг 2), потом шаги 3–5. Проверка текста без сценария под рукой: средняя правдоподобность звука слов в новом
ролике (модель `fa.py`) та же, что в старом (−47,8 против −47,5), пауз больше 0,2 с внутри фраз нет.
